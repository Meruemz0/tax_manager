# 第一阶段数据方案

## 当前项目

根目录的 `init.sql` 已定义 `customers`、`monthly_filings`、`customer_images` 三张表。`demo/init.sql` 在此基础上提供独立可执行的建表和演示数据脚本，`demo/upgrade_v2.sql` 在已运行的 Demo 数据库上增加注册日期、逐月记录、255 字备注限制和标签分类；`demo/src` 是对应的网站程序。网站已通过 SSH 隧道连接数据库；升级 SQL 仍需在目标数据库执行。

## 数据划分

| 数据 | 存储方式 | 说明 |
| --- | --- | --- |
| 客户资料 | PostgreSQL `customers` | 保留客户编号、名称、税号、联系人、注册日期和最多 255 字备注。 |
| 每月报税情况 | PostgreSQL `monthly_filings` | 从客户注册月到中国时间本月，每客户每自然月一行；`tax_month` 使用当月 1 日，可修改历史月份。 |
| 标签分类 | PostgreSQL `tag_categories`、`customer_tag_categories` | 用户可新增分类，并给客户关联多个分类。 |
| 与客户关联的图片 | 文件存储 + PostgreSQL `customer_images` | 原图放在持久化目录；数据库只存客户 ID、随机文件键、文件类型、大小等元数据，便于按客户查询。 |
| 无序图片 | 单独的持久化目录 + PostgreSQL `unassigned_images` | 预计不超过 100 张，需要浏览、下载和删除，所以保留最少的文件目录信息。没有名称、时间等业务检索索引；按主键取单张。 |
| 网站账号 | PostgreSQL `site_users`、`login_attempts` | 用户名唯一；只保存加盐的 scrypt 密码哈希，登录失败次数由数据库共享计数。SQL 预置账号 `wfg1`，首次登录前需私下设置密码。 |

公开首页无需登录；客户、报税和图片信息及操作需要登录。图片由网站鉴权后读取，存储目录不能直接公开。上传时校验真实文件格式、大小和像素数；目前不强制图片总数上限。数据库与图片目录需要一起备份，并定期验证恢复；只备份 PostgreSQL 无法恢复图片。

## 部署要点

1. 在目标 PostgreSQL 数据库依次执行 `demo/init.sql` 和 `demo/upgrade_v2.sql`；已有数据库只需执行尚未运行的升级脚本。两个脚本均可重复运行，不会覆盖已报税状态。
2. 为网站配置一个持久化、非公开的图片目录；SQL 只建立元数据表，不会在 Linux 上创建目录或 Docker 卷。
3. 网站程序已按认证、客户、图片和数据库职责分模块，使用随机文件键。删除时先提交元数据变更，再清理文件；失败时报告，使用 `images check-files` 命令核对差异。
4. 网站首页公开，工作台、业务接口及图片访问都需登录；登录按 SQL 中标明的 scrypt 参数校验 `site_users` 表中的哈希。通过交互式 `auth set-password` 命令设置新密码。程序在图片目录中自动创建 `.session-key`，无需手动配置密钥。运行命令详见 `demo/README.md`。

## 已确认条件

- 月份按中国时间计算，从客户注册月份逐月记录；状态只需“未报/已报”。
- 无序图片预计不超过 100 张，约为普通 Linux 截图大小，并需要浏览、下载、删除。
- PostgreSQL 在局域网内另一台 Linux 机器的 Docker 容器中，通过 SSH 隧道访问；目前有演示客户数据。
